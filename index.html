The problems, the decisions I made and what changed.

Breaking up a legacy enterprise monolith

Global Rescue, as a core engineer on the migration

Problem
A single EJB, Servlet and JSF application served every client. Releases were slow and risky, and a fault anywhere could affect all 80,000 users.
What I did
Built Spring Boot services as the platform was split by business capability, including the traveller-tracking module. Migrated 2M+ records for 40+ enterprise clients and moved 100% of users to Keycloak SSO with OAuth2/OIDC.
Outcome
22+ independently deployable services, with release cycles cut from weeks to days. The tracking module helped win 3+ new enterprise clients.
  • Java 17
  • Spring Boot
  • JPA/Hibernate
  • Keycloak
  • MySQL
  • PostgreSQL

Moving slow work off the request path

Global Rescue, a decision I proposed and drove

Problem
User-facing APIs waited on synchronous calls for work users didn't need to wait for, and low-priority traffic was delaying time-sensitive messages.
What I did
Moved non-critical inter-service calls to RabbitMQ events, with priority queues, retries and dead-letter queues so failures were handled rather than lost.
Outcome
API response times fell by 23%, and time-sensitive customer journeys were protected from background load.
  • RabbitMQ
  • Spring AMQP
  • Event-driven design

Rebuilding search for speed

Global Rescue

An AI product, shipped end to end on free-tier cloud

Road traffic accident detection, my MSc project (Distinction)

Problem
Accidents are usually reported by witnesses, which delays the response. The goal was to detect them in dashcam video and alert a live dashboard within seconds.
What I did
Took it from requirements to deployment: a FastAPI inference service on Google Cloud Run, PostgreSQL and Cloudinary for incidents and video, Auth0 securing REST and WebSocket endpoints, and a React dashboard with a live incident map. I kept the model behind its own service boundary so I could later swap in a stronger one without touching the rest of the system.
Outcome
Live updates to every connected dashboard. Accuracy rose from 59.4% to 73.8% after the model rebuild, and the whole stack ran on free tiers.

  • PostgreSQL
